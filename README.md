## 失败处理与本机运行边界（F25）

此次只补交付可靠性与安全边界，原研究点、AIS、保存案例、90 m / 15 m/s / 建筑 30 m 和官方 SST 搜索没有改动。

- **本机访问**：启动器为本项目新建的 Java 17 进程启用回环绑定，覆盖模型 HTTP、编辑器通信与数据库辅助端口；动画控制端口同样只允许本机连接。不修改已安装的 AnyLogic 文件，也不要求管理员权限。网络保护无法生效时会明确拒绝启动。当前固定验收 AnyLogic 8.9.10 PLE 所带 Java 17，其他引擎/JVM 不承诺兼容。
- **先验文件和显示来源**：正常启动检查不可变执行文件、JAR、输入控件、模型和显示资源的发布大小/哈希；并从原始 AIS 重新对应工作台的坐标、时间、片段及投影，拦截混版和错误派生显示。合法新增结果按其自身请求/来源检查，不能为通过校验而直接更新发布清单。
- **有限等待**：单次 Python 桥接/规划作业整体上限 180 秒，Windows Job Object 负责所属 Python/SST 子进程；超时、非零退出、缺少返回文件均清除旧成功画面并恢复任务控件。关闭模型时回收所属作业。系统进程查询另有 15 秒上限，模型初始化上限 180 秒。
- **损坏结果**：`latest.json` 损坏或来源/投影不符时准备流程会失败。需要回到原保存默认结果时，双击 **恢复默认结果.cmd**；它先把损坏文件留在 `.local/recovery/`，再恢复原快照，不把恢复说成新规划成功。合法新结果保留。
- **输入与错误**：拒绝 bool/null/错类型/非有限数、错误经纬度、无效时间和研究点结构；数据尚未验证时以空来源错误返回，不编造来源。输出目录无权限或写盘失败会报告错误，不能沿用上一次成功。
- **启动和重试**：同目录启动全流程加锁，记录 `starting/ready/failed` 与创建时间；首次接管窗口也核对项目、模型、工作区、JVM 和进程创建时间。失败清理只针对本次所属进程。保留最近三次会话缓存，旧会话只在进程已退出且生成模型未被编辑时清理，并保留诊断日志；改过的模型和运行结果不会按缓存删除。

出现问题时先运行 **检查运行环境.cmd** 和 **验证项目数据.cmd**。日志位于 `.local/launcher-state.json` 指向的位置、`.local/jobs/` 和 `anylogic/visual_demo/controls_setup.log`。中文目录通过 Unicode 解压处理，不依赖 Windows 的系统语言；极长目录仍受 Windows 组件路径长度限制，依赖验证失败时先移到较短目录。文件被杀毒隔离、下载缺件或磁盘不可写时，应恢复完整可信副本或选择可写目录后重试；不要关闭系统防护来绕过错误。

维护者回归命令：`runtime\python\python.exe -B -m unittest discover -s tests -v`。仓库还提供 Windows GitHub Actions，使用仓库自带运行库与数据在全新运行器的中文空格路径下检查并重算；它不安装 AnyLogic，不能替代其他物理电脑上的图形界面验收。详细修复、证据和未验证项见 [`docs/F25/修复与验收.md`](docs/F25/修复与验收.md)。

## 项目制作思路：先明确数据能说明什么，再实现规划和演示

项目要研究的是：**在维港已有船舶观测和建筑约束下，一架无人机能否从指定巡航点按时出发，到达另一个巡航点；直飞不满足约束时，能否找到一条合格绕行路线。** 当前交付围绕这个问题，采用以下步骤：

1. **保存可追溯的输入。** 船位来自真实 AIS 接收记录；建筑和码头参考来自官方开放数据。保存原始消息、下载请求、加工规则和 SHA256，使界面上的结果能追到原件。
2. **明确缺测。** 相邻合格观测之间采用原规则线性插值，长缺口及观测首末之外标为未知。不能为让任务成功而移动船舶、编造连续船位或更换出发时刻。
3. **固定研究任务。** 用官方渡轮码头作为地理锚点，派生海上巡航门点，冻结八点和四条线路。它们用于比较规划行为，尚不代表码头起降、装卸或完整物流作业。
4. **在统一米制坐标中计算。** Python 使用 EPSG:32650，将无人机、船和建筑放在同一距离口径下；先检查起点与直飞路线，直飞通过就直接使用，起点已冲突就拒绝该时刻出发。
5. **必要时调用官方规划库。** 通过本地进程调用 OMPL 2.0.2 `control::SST`。状态包含二维位置和时间，控制为航向，无人机按设定速度匀速运动；目标是在满足硬约束时减少航程。当前未建模加速度、转弯半径和垂直起降，也不承诺找到全局最短路线。
6. **复核整条轨迹，再显示。** 原几何/连续时间检查核对建筑、已观测船舶、端点和时间。AnyLogic 通过本地文件及 Python 子进程加载或重算结果，飞机和船共用一个时钟。三维相机和楼体用于帮助观察，计算仍是二维。

这样分工的理由是：Python 保留数据处理、官方库适配和独立验证，AnyLogic 负责原生仿真交互；两部分复用同一份结果，不另写一套展示端寻路算法。**加载保存案例是读取原结果；点击工作台重新规划才会提交新计算。** 求解失败和数据未知都是需要保留的结果。

实现对应：[`src/ais_replay.py`](src/ais_replay.py)（观测分段）→ [`src/ais_single_task.py`](src/ais_single_task.py)（任务与参数）→ [`src/ompl_sst.py`](src/ompl_sst.py) / [`sst_probe.cpp`](runtime/ompl/sst_probe.cpp)（官方 SST 适配）→ [`src/anylogic_workspace.py`](src/anylogic_workspace.py) / [`ais_anylogic_bridge.py`](ais_anylogic_bridge.py)（工作台桥接）→ [`NativeDemoView.java`](anylogic/NativeDemoView.java)（显示）。库接口含义可查 [OMPL 官方 SST 文档](https://ompl.kavrakilab.org/core/classompl_1_1control_1_1SST.html)，本项目固定版本身份见 [`runtime/ompl/manifest.json`](runtime/ompl/manifest.json)。

## 各种数值为什么这样设

下面区分**外部资料参考、当前样本推导、研究假设、计算设置和显示设置**。来源能解释取值，不等于它已被标定为现实飞行安全参数。原参数账本见 [`config/parameter-sources.json`](config/parameter-sources.json)；其中仍保留部分旧算法字段，实际生效情况应结合 [`src/ompl_sst.py`](src/ompl_sst.py)、[`runtime/ompl/settings.json`](runtime/ompl/settings.json) 和各次运行的 `planning_config.json` 判断。

### 运动、避让与坐标

| 数值 | 来源与设定理由 | 当前含义与限制 |
|---|---|---|
| **无人机 15 m/s** | 参考 [DJI FlyCart 30 官方支持页](https://www.dji.com/support/product/flycart-30) FAQ 中的最大航线速度，将其用作本项目恒速研究值。 | 不是实测平均配送速度，也未复现 FlyCart 30 的整机性能。官网另列 S 模式 20 m/s，不能混同；本项目未接入 DJI 控制 API。 |
| **统一船体包络 60 m** | 对本批四艘具有完整 AIS 尺寸的船计算参考点到最远船体角的距离，最大约 57.870545 m，向上取为 60 m。 | 取整并统一应用于其他缺尺寸船是已确认的研究简化；不是维港最大/平均船体尺寸。 |
| **船位参考点避让半径 90 m** | `60 m 船体包络 + 30 m 研究净距`。 | 是相对 AIS 位置参考点的模型半径，不是距离真实船舷 90 m。未完整计入无人机尺寸、定位、插值和控制误差，不能据此保证现实净距。 |
| **建筑包络外 30 m** | 借鉴 [香港民航处相应标准操作类别的横向间距数值](https://www.cad.gov.hk/english/sua_safetyreq_operatingreq.html)，在官方轮廓派生的保守投影包络外检查。 | 这是项目的研究适配，不是对某段真实建筑立面的测量结果；保守包络也可能拒绝现实中可行的路线。 |
| **EPSG:32650** | 通过 pyproj/PROJ 使用 WGS84 / UTM 50N，让当前研究区域的规划与回放统一以米计算。 | 不再把经纬度差直接当米；旧局部投影的端点生成偏移值保留历史身份，不当作当前 UTM 精确量距。 |
| **0.001 m** | 原浮点比较中的数值余量。 | 不是毫米级 GPS 精度、地图精度或额外实飞误差保障。 |

30 m 所参考的 CAD 类别同时有速度等条件；**15 m/s = 54 km/h**，不能把本模型“15 m/s + 30 m”写成满足相应 **50 km/h** 标准条件的合规配置。厂家速度和官方间距在这里分别提供数值参考，不构成批准航线。

60 m 的推导可以复算。AIS 尺寸 A/B/C/D 表示位置参考点到船体相应边界的距离，含义参考 [USCG AIS 消息说明](https://www.navcen.uscg.gov/ais-class-a-reports)。本项目不假设参考点位于船体中心，采用：

```text
R_ship = sqrt(max(A, B)^2 + max(C, D)^2)
```

| 本批样本 MMSI | A/B/C/D（m） | 推导 R_ship（m，约） |
|---|---|---:|
| 413775272 | 3 / 57 / 10 / 6 | 57.871 |
| 413955285 | 44 / 6 / 8 / 5 | 44.721 |
| 413867408 | 2 / 48 / 8 / 8 | 48.662 |
| 413788101 | 6 / 54 / 10 / 6 | 54.918 |

样本不足以推导全区域统一安全半径；本项目明确接受简化后才固定使用 60 + 30 = 90，不能把这四艘的样本最大值外推为所有船的真实上界。

### AIS 质量、缺测与研究点

| 数值/规则 | 为什么设、怎样用 |
|---|---|
| **相邻观测间隔 ≤120 s 才能在合格片段内插值** | 原工程的数据质量门槛，沿用以便复现。服务商没有规定“120 s 插值必然准确”，本项目也未独立标定其位置误差。长缺口断开，首末观测之外不外推、不假设停留；孤立观测只在该时刻有效。 |
| **推算船速上限 30 m/s** | 原跳点/异常筛查阈值，不是所有真实船舶的物理最高速度，也不是无人机速度。 |
| **报告过旧 120 s、未来偏差 5 s** | 采集基础校验中的时间异常阈值，属于未标定工程设置，和相邻点插值上限用途不同。 |
| **一小时采集、923 消息/130 船** | 前者是实验采集时长选择，后者是这次数据统计；不证明连续一小时完整覆盖。 |
| **旧字段 600 s** | 仅保留原质量配置/历史审计身份。当前 `observed_segments_v3` 不要求每条任务先获得整船连续 600 秒观测；不能据此恢复旧拒绝门槛。 |
| **区域纬度 22.27—22.32，经度 114.12—114.27** | 项目框选的维港研究范围，不是行政边界或无人机获准飞行区。部分背景下载范围额外留边，不改变任务研究范围。 |
| **8 点、4 条任务** | 以短/长距离及端点建筑余量的功能覆盖为设计思路，从官方渡轮首末站候选按既有几何规则筛选得到；不是某篇论文规定必须八点。 |
| **选点步长 25 m、最大偏移为连线长度的 1/3** | 原离散选点工程规则，沿码头连接方向寻找静态可行且位于已有航道面内的巡航门点；不是法定退岸距离。选定后冻结，不再为成功率移动。 |
| **冲突案例扫描 5 s、方向分组 45°/135°** | 分别是原实验的出发时刻采样网格和描述性几何分类；可能漏掉网格之间的情况，也不是海上避碰规则分类标准。 |

四条固定任务为 M1 尖沙咀—中环、M2 北角—红磡、M3 西湾河—三家村、M4 尖沙咀/尖东—鲤鱼门。起终点在海上，是**官方码头锚点派生的巡航门点**，不是获批起降点。固定出发请求、八点坐标和来源身份保存在离线包内的 `output/research_points/study/`。

当前缺测处理是已确认的研究假设：**有有效观测位置就检查；未知时段单列，不因缺口本身拒绝任务**。因此“通过已观测船舶避障检查”不等于“已排除未知船舶风险”。原参数、源数据和起点冲突不能为了演示成功而更换。

### SST 的数值是求解设置，不能当作安全标准

| 设置 | 当前值及依据 |
|---|---|
| **求解预算** | 普通需绕行短任务 10 s，固定建筑 M4 为 60 s；是既有试验和回归后选用的计算耗时预算，数据加载/复核另计。直飞合格或起点拒绝时无需启动搜索。超时未得合格解就如实失败。 |
| **随机种子** | 正式设置 42；此前用预定 42/43/44 回归。用于可复查的随机试验条件，不是找不到就无限换种子重试。预算相同也不保证跨机器结果逐点相同。 |
| **传播步长 0.1 s，控制 1—50 步** | 单次航向控制持续 0.1—5 s，属于数值传播设置，不是 AIS 发报周期或只每 0.1 秒检查一次安全。 |
| **普通选择/剪枝半径 0.2 / 0.01，goal bias 0.2** | 官方 SST 的公开算法设置。状态按原直线距离 L 和直飞时间 L/v 归一化；这些数值不是米，也不是成功概率或实飞保护距离。 |
| **固定 M4 选择/剪枝半径 75/L、1.5/L** | 75 m = 15 m/s × 最长 5 s 控制，1.5 m = 15 m/s × 0.1 s 传播；据此调整长任务的公开参数。状态距离还包含时间，不能解释成纯空间安全球。 |
| **候选终端范围：普通 15 m、M4 75 m** | 分别借用 1 s/5 s 飞行距离作为内部候选范围。必须再从候选点实际飞到原终点，末段计入时间/距离并通过原检查；不允许在离终点 75 m 的地方冒充到达。 |
| **固定请求查询时长** | `settings.json` 保存既有固定请求的原可行航时上界，相向还受原参考船片段剩余时间限制；用来界定本次搜索域，未把旧路线坐标喂给 SST。自定义时间不匹配固定请求时使用原记录范围和默认设置，没有任意请求都成功的保证。 |
| **旧网格 200 m、展开上限 20000、旧软惩罚权重等** | 配置/来源账本中的兼容字段不等于当前算法仍做旧 A*。200 m 仍作为相关空间处理尺度传递，但当前 SST 在连续状态中采样；不把 20000 宣称为 SST 的有效展开预算，也不以旧软代价解释当前“硬约束下航程优先”目标。 |

算法库的“内部精确解”标签还必须通过本项目的原端点、整程时间和独立约束复核，才算项目任务成功；库返回结果本身不替代验收。详见 [OMPL SST 设置接口](https://ompl.kavrakilab.org/core/classompl_1_1control_1_1SST.html) 和本仓库适配源码。

### 怎样自行核对一个数字

1. 先区分它是输入参数、观测统计、求解设置、显示设置，还是某次模型输出，不把输出当作预先规定的常数。
2. 在 [`config/parameter-sources.json`](config/parameter-sources.json) 查原账本，在 [`runtime/ompl/settings.json`](runtime/ompl/settings.json) 查本次固定求解设置，在 Java/输入脚本查显示值。
3. 首启解压后，核对相应 `request.json`、`planning_config.json`、`result.json`、官方来源清单及原始行；结果里的 `run_id` 和哈希用于区分运行身份。旧账本中的未启用字段不能套作当前生效设置。
4. 用“验证项目数据.cmd”检查原件与运行库身份。只有本轮证据覆盖到的检查才能称已验证，页面画得更细或文件来源官方都不能自动扩大结论。

## 研究范围

当前是**离线历史 AIS、单架无人机、二维海上巡航段**；三维仅用于展示，不含码头起降、实机控制或未来船位预测。90 米船距、15 米/秒、30 米建筑间距沿用原研究配置，并非飞行许可。缺失船位按已确认的原规则单列未知；结论限于已观测船舶。六个演示入口不是六个独立遇船实验，孤立点与相向共享一次出发。六个只读入口中的历史实验不能当作新 SST 性能结论。不保证任意时刻求解成功或全局最短。
