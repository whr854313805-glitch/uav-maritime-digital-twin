## 软件与交付风险

| 项目 | 事实与影响 | 当前可接受的条件 |
|---|---|---|
| 目标实体机 GUI 未验（P1） | 全新 Windows 后端通过，但另一台组员 Win10/11 的 AnyLogic/GPU/安全软件完整链路未验证。 | 仅作为试运行交接，按[实体机验收表](测试说明.md#组员实体机验收表尚未执行由接收人填写)补验；正式交付签字仍被此项阻挡。 |
| 新 latest 与目录缓存 stale（P2） | 合法新结果和工作台目录的自动刷新闭环未完全打通，自检可报 `Workspace is stale for current`。 | 短演示使用原保存案例；验证重算使用 `publish=False` 的既有命令。出现 stale 时保留新结果及日志交维护者，不恢复/覆盖合法新结果来掩盖。若接收范围要求反复发布新默认结果，此问题不能算已接受。 |
| 极长目录（P2） | 209字符根目录压力测试曾失败，未消除 Windows/依赖的路径限制。 | 只在 `C:\uav` 等较短可写路径接收；不承诺任意长度目录。 |
| 资源峰值与长时稳定性（P2） | 曾在测试和大数据自检并行时出现4个 MemoryError，随后串行通过；根因未定位，未形成低配置/长时证据。 | 先串行验证、单次规划、短时演示；不能承诺无人值守或低内存长期运行。异常保留日志，不擅自归因为用户电脑。 |
| 覆盖仍有限（P2） | 当前最终版CI实际新算2入口，尚非10入口全量；数值/故障边界组合未穷尽。 | 结论限于记录覆盖场景。扩大接收范围前需补证据，不能用保存案例或旧版本报告替代。 |
| 固定依赖环境 | 仅交付 Windows x64；AnyLogic 8.9.10 PLE需单独安装，当前依赖其Java17/Chromium；其他平台/版本未逐一验证。 | 接收人同意此环境要求并完成首次启动；仓库不分发 AnyLogic 许可证。 |

本表 P1 指阻止正式交付验收，P2 指需处理或明确接受边界；不是漏洞利用等级。当前不签“任何组员电脑都已证明可运行”。

## 研究结论的适用范围

| 限制 | 为什么在本次研究交付中保留 |
|---|---|
| 历史 AIS 不完整，未知船位不参与避障 | 已确认的观测模型假设；报告未知，不伪造船位。允许研究已观测约束下的规划行为，不能证明现实无碰撞。 |
| 单机、二维巡航段，未建模起降/动力学/天气 | 当前问题只覆盖固定海上点之间的二维规划。三维楼体与飞机高度为展示；不外推成实飞或物流系统。 |
| 90m/15m/s/建筑30m为研究配置 | 有原样本/外部参考/项目假设说明，未完成真实无人机误差与全船体标定；不视为运行许可或安全认证。 |
| SST有预算和随机性 | 给定预算可能未找到合格解，跨机器路线不必逐点相同；失败不等于证明无路，成功不等于全局最优。 |
| 六演示不是六独立实验 | 孤立点与相向共享一次出发；只读历史网格条目不属于当前SST新实验。展示数量不用于扩大统计结论。 |

这些限制与离线研究演示定位一致；若用途改成实时航行、实飞控制或对外安全承诺，就不能沿用本次“可试运行”的接受判断。

## 遇到失败先留下什么

记录完整提交号、操作顺序、错误文字及时间；保存 `.local/verification.json`、`.local/launcher-state.json` 指向的日志、相关 `.local/jobs/` 日志，控件问题补 `anylogic/visual_demo/controls_setup.log`。先用环境/数据检查定位；不要改原始船位、冻结点、阈值、执行文件或发布清单来获得绿灯。

`恢复默认结果.cmd` 会备份损坏结果再恢复原快照，只用于明确需要恢复的损坏结果；它不是新求解成功，也不是合法新结果刷新问题的通用修复。当前网络服务设计为本机回环，不提供跨电脑访问或部署承诺。
