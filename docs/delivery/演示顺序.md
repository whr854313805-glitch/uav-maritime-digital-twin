# 四分钟演示顺序

[启动入口](../../README.md) · [设计](设计说明.md) · [测试](测试说明.md) · [风险](风险与限制.md)

演示前先启动并完成环境/数据检查，打开[测试说明](测试说明.md)备用；确认本机版本、窗口和保存案例能加载。以下按钮均为当前原生界面已有按钮。案例加载期间等结果就绪后再操作；本表时间是讲解预算，不是加载性能保证。

| 时间 | 操作 | 只讲这一点 |
|---|---|---|
| 0:00—0:20 | 显示整体画面 | “这是历史 AIS 下的单机二维巡航规划；Python 计算，AnyLogic 展示，三维不代表三维避障。” |
| 0:20—0:55 | “正常直飞”→“回到出发”→“演示播放/暂停”，切换二维/三维 | 直线通过就直接飞，紫色航迹与船共用时钟；当前加载的是已保存结果。 |
| 0:55—1:40 | “相向避让”→“跳到直飞冲突”→“跳到最近船距” | 灰线/红点是直飞对照，紫线是合格绕行；船保持原 AIS 轨迹。这里的相向不是严格180°对撞。 |
| 1:40—2:20 | “建筑避障”→“跳到最近建筑”，切换视图；可短暂播放 | 原建筑包络参与二维计算，楼体只是展示；M4默认10倍，可拖1—10倍速度条。倍速不改变15m/s物理速度。 |
| 2:20—2:45 | “起点拒绝案例” | 已知起点船距不够就不出发：应显示拒绝原因，没有无人机和旧成功路线。拒绝也是正确结果。 |
| 2:45—3:10 | “孤立观测点”，短暂播放后再次点该按钮 | 只在真实观测时刻有船位，前后不补造；它与相向共享一次出发，不当作另一个独立实验。 |
| 3:10—3:40 | 展示已保存的验证报告或[对应Windows工作流](https://github.com/whr854313805-glitch/uav-maritime-digital-twin/actions/workflows/windows-offline.yml) | 本机已通过68自动化、9基础和2实际重算；远程状态看对应提交；六保存案例播放另有本机GUI证据。自动化后端不代替组员实体机GUI。 |
| 3:40—4:00 | 打开[风险与限制](风险与限制.md) | 说明未知船位、二维、预算求解和实体机待验；当前交付用于组内试运行。 |

若只有两分钟：保留“正常直飞→相向避让→起点拒绝→验证与限制”，跳过建筑/孤立点的现场操作。若还有余量，再展示“同向绕行案例”、中键平移、Ctrl滚轮缩放与重置相机。

## 需要证明现场新算时

另留时间点“演示 / 工作台”→选“固定任务”下的 M2→核对原出发时间→点“按此时间规划”。展示本次新 `run_id` 和检查摘要；不要把“读取原结果”称为重新规划。M2可能直飞通过，不据此声称展示了SST搜索；相向新算可另作专项。

加载/复核耗时不包含在求解预算内，M4搜索预算为60秒、单次桥接整体上限180秒，不承诺现场几秒必成。工作台新算生成本次运行；需要发布默认结果的原命令行入口会同步目录，无需手动刷新。短演示不依赖现场新算完成，CLI的两项验证重算不会覆盖保存案例/latest。

失败就展示原错误与日志；不临时换时间、调低阈值或改船位追求成功。演示中不手改JSON注入错误，校验故障的既有记录见 [F26 验收](../F26/修复与验收.md)。
