## 实现依据与新增工程数值

- [Oracle Java 17 Instrumentation API](https://docs.oracle.com/en/java/javase/17/docs/api/java.instrument/java/lang/instrument/Instrumentation.html)：类加载转换、模块导出与重转换的接口依据。具体 Net.bind 方法匹配来自本机 AnyLogic 所带 Java 17 字节码核查；本项目实现进程内绑定替换，未声称它是 AnyLogic 官方配置选项，也不分发被修改的引擎/JRE。
- [Microsoft Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)：所属进程分组、子进程继承和关闭 Job 时回收的接口依据。这里将非继承 Job 句柄留在监督进程，另监测原模型父进程句柄，避免强制关闭 Java 后遗留作业。
- 总作业/初始化 180 s 是工程截止时间：给原最长 60 s SST 预算另留数据加载、原检查与界面准备余量，并使挂起可恢复；不是实测所有电脑都能在此期限内求解。CIM 15 s 用于明确停止无界系统查询；三份近期缓存用于保留近期诊断并限制重复启动的磁盘积累。它们不改变研究安全参数，不保证慢电脑必定成功。
- 代码位置及 SHA256 见 `code-map.json`；当前源 JAR 已因上述修复重建，F23 原 JAR 的旧哈希仅保留为历史身份。

### 搬迁补验发现并修复的界面异常

在中文空格路径的纯发布副本里，AnyLogic 初始化重绘曾留下不再属于当前 world3d 的 canvas，旧 canvas 位于左上角拦截播放按钮。F25 输入适配 v3 仅清理引擎已不再引用的三维 canvas，并禁用非活动窗口画布的指针接收；保留当前活动场景和相机。验收增加退休画布注入、活动画布保留及搬迁副本六入口/播放回归。

启动会话另记录不可变运行文件的发布身份；源码/输入脚本版本改变后不复用旧会话。文档/新结果更新不因版本检查被一律拒绝。

中文空格路径发布副本补验已通过：首启自动准备离线 Python 与 140 原件、全新 AnyLogic 会话、v3 输入适配，以及全部六入口的二维/三维和实际播放回归。迁移证据见 `portable-six-cases.json`；该测试仍发生在同一物理电脑。

### 全新英文 Windows 发现的首启问题

首轮 GitHub Windows 运行器已成功下载全部 Git 文件，但 Windows tar 将中文目录转换为问号，首启解压失败。已改为 .NET ZipArchive 流式解压，路径始终保留 Unicode；继续检查逐项目标路径、原压缩包哈希和93个关键文件。验证使用受控的新进程并设置120秒截止，固定依赖/压缩分片未更换。新的本机中文目录首次解压及二次启动关键文件复核通过；远程重试见 Actions。

极长目录仍有 Windows 原生组件路径边界：根路径209字符的额外压力测试中解压可完成，但临时运行环境的依赖验证未能通过，已明确报错并保留正常版本；未宣称已支持任意路径长度。建议将整个工程放在 C:\uav、桌面或下载目录等较短可写路径。此项列为已知平台限制，不用改变系统防护或注册表绕过。
